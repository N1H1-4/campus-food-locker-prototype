# 校园智能外卖柜 · 三端联动原型

> 课程大作业《物流项目管理》配套原型。**纯前端**（HTML + CSS + 原生 JS），无构建、无依赖、无需 npm install。
> 唯一数据源：`任务书/项目任务书_v1.md`。原型内所有点位、柜型、组数、格口数、工期、概算、效益口径均取自该文件，未另算一套。

## 一、如何打开

1. 双击 `原型/index.html`（推荐 Chrome / Edge；不建依赖，离线可用）。
2. 首次打开会自动灌入模拟种子数据（6 点位 / 34 组 / 1,360 格口 / 78 笔历史订单 / 3 张工单），并写入 `localStorage`（键名 `WL_CABINET_PROTO_V1`）。
3. 右上角「模拟时钟」可快进 1h / 3h、回真实时间、重置演示数据——用于在不等待 2 小时的情况下演示超时预警与超时费。

> 不要用无痕窗口打开（关闭即丢数据）。若浏览器禁止本地存储，页面顶部会出现红色提示条（此时数据仍在内存中，仅刷新会重置）。

## 三、三端功能（共用同一份 localStorage 数据）

### ① 骑手投柜端
- 6 个点位卡片：点位名、柜型（超大/大/小）、组数、格口总数、剩余格口、报修格口、占用率、按温区的可用数。
- 选点位 → 选温区（常温 / 保温）→ 系统推荐可用格口（规则：温区匹配 → 占用率最低的柜组 → 主柜优先 → 格口号升序），可手动切换备选格口。
- 「模拟扫码开柜 · 投柜」→ 柜门打开 → 写入订单 → 生成 **6 位取餐码**，格口状态变为占用。

### ② 用户取餐端
- 输入 6 位取餐码（或在柜订单快捷填入）→ 显示点位、柜号（组号 + 主/副柜）、格口号、温区、存放时间、已存放时长。
- 超时提醒 + 超时费计算式（逐步显示数字与公式）。
- 「开柜取餐」→ 订单状态变「已取餐」，格口释放回可用池，记录超时费。

### ③ 运营后台
- **点位看板**：8 个汇总指标 + 6 点位明细（格口总数/占用/空闲/报修/占用率/今日投柜/周转次数）。
- **实时订单**：骑手端刚投的订单立即出现；支持按点位与状态筛选。
- **超时预警**：在柜且存放 > 120 分钟的订单，含已存放时长、超时分钟、预估超时费、推送催取。
- **运维工单**：新建报修（点位 + 柜组 + 故障类型 + 描述）→ 该柜组空闲格口置为「报修停用」→ 待处理 → 处理中 → 已修复（格口自动恢复可用），全程留处理日志。
- **KPI 报表**：日投柜量、超时率、格口周转率（按当前模拟数据实时计算并给出算式），并列出任务书口径（2,310 单/日、0.80 元/单、698,400 元、3.61 年等）作为对照。

## 四、演示脚本（约 90 秒走通全链路）

1. 骑手端 → 点 `P2 A区14公寓与A区食堂之间` → 选「保温区」→ 读到推荐格口（如 `P2-G05 主柜 03`）→ 点「模拟扫码开柜 · 投柜」→ 记下 6 位取餐码。
2. 点「去用户端用此码取餐 →」（或顶部导航到用户端手动输入）→ 看到点位/柜号/格口号/温区/存放时间 → 点「开柜取餐（免费）」→ 页面显示「已取餐」，格口释放。
3. 运营后台 → 「实时订单」页签：能看到刚才那笔（状态已取餐）；「点位看板」剩余格口已恢复。
4. 运营后台 → 「超时预警」：站内有 3 笔种子超时订单；回用户端输入其中一笔的码，可见红色超时提醒与「超时费 = ⌈(存放分钟−120)÷60⌉ × 1.00 元」的完整算式。
5. 运营后台 → 「运维工单」：选点位 P5、柜组 P5-G01、类型「柜门卡阻」，提交 → 出现「待处理」→ 点「受理」变「处理中」→ 点「修复完成」变「已修复」；同时看板「报修停用」格口数先增后减。
6. 按 F5 刷新：订单、取餐、格口状态、工单全部保留（localStorage）。

## 六、假设值（任务书未规定，页面内已标注）

1. **超时计费**：免费存放 120 分钟；超出后每满 60 分钟（不足 1 小时按 1 小时计）加收 1.00 元；单笔封顶 5.00 元。
2. **故障停机**：工单创建后该柜组当前空闲格口置为「报修停用」，修复完成自动恢复。
3. **演示种子数据**：近 4 日 78 笔订单 + 3 张工单，仅用于让看板与 KPI 有初始分布，**不是调研数据**。
4. **格口周转率口径**：当日投柜笔数 ÷ 格口总数（次/格口·日）；任务书的规划口径为 2,310 ÷ 1,360 ≈ 1.70。
5. **温区划分**：每组 40 格中 10 格为保温区（主柜 4 + 副柜 6），34 组 × 10 = **340 格口**，与概算第 4 项「保温/加热分区改造 340 格口（25%）」一致。

## 七、自检脚本

```bash
node tests/selftest.js      # 数据/业务逻辑 117 项断言（点位、链路、计费、工单、持久化、三视图渲染冒烟）
node tests/wiring-check.js  # 事件接线 26 项断言（data-action 全覆盖、DOM id、资源本地化、UI 动作直调）
node tests/browser-check.js # 实机浏览器自动点击验证（需本机 Chrome/Edge；会在 tests/screenshots 下截图）
```

> 端到端链路（骑手投柜 → 后台可见 → 用户取餐 → 格口释放）在 selftest.js 第 3 节逐条断言；
> browser-check.js 用 CDP 驱动真实 Chrome 走同一链路，本机若装了 Chrome 可直接复跑。
