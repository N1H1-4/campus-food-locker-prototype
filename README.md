# 校园智能外卖柜 · 三端联动原型

**在线演示：<https://n1h1-4.github.io/campus-food-locker-prototype/>**

> 《物流项目管理》课程大作业配套原型。纯前端（HTML + CSS + 原生 JS），无构建、无依赖、无需 npm install。
> 项目：哈尔滨商业大学北校区校园智能外卖柜末端配送体系建设项目（6 点位 / 34 组柜体 / 1,360 格口 / 在校师生约 15,000 人）

---

## 一、在线怎么玩（2 分钟走完主流程）

打开 <https://n1h1-4.github.io/campus-food-locker-prototype/>，顶部有三个页签：**骑手投柜端 / 用户取餐端 / 运营后台**。

1. **骑手投柜端** → 点点位卡片 P2（A区14公寓与A区食堂之间）→ 选「保温区」→ 点「模拟扫码开柜 · 投柜」→ 记下 6 位取餐码
2. **运营后台** → 「实时订单」首行就是刚投的那单 → 「超时预警」看超时单与超时费公式
3. **用户取餐端** → 输入取餐码 → 显示点位 / 柜号 / 格口号 / 温区 / 免费剩余分钟 → 点「开柜取餐」→ 格口释放
4. **运营后台** → 「运维工单」新建报修 → 状态流转 待处理 → 处理中 → 已修复 → 「KPI」看日投柜量与格口周转率
5. **刷新页面** → 数据仍在（localStorage）

> 演示超时不用等：右上角「模拟时钟」可快进 1h / 3h，用于触发超时预警与超时费计算。

## 二、三个端做了什么

| 端 | 核心功能 | 对应项目活动 |
| --- | --- | --- |
| 骑手投柜端 | 选点位 → 按温区推荐格口（占用率最低柜组优先、主柜优先、格号升序）→ 扫码开柜 → 生成取餐码 | 运营流程与骑手协同方案（活动 G） |
| 用户取餐端 | 取餐码查询 → 格口定位 → 开柜取餐 → 格口释放 → 超时提醒与超时费 | 系统需求与原型设计（活动 F） |
| 运营后台 | 点位看板（占用率/周转率）→ 实时订单 → 超时预警 → 运维工单三态流转 → KPI 报表 | 原型设计 + 效果评估（活动 F、S） |

三端**共用同一份模拟数据**（data/store.js），骑手端写入的订单会在后台与用户端立刻可见，形成业务闭环——不是三个互不相干的演示页。


## 五、本地运行

双击 index.html 即可（推荐 Chrome / Edge），离线可用，无需任何依赖。

> 不要用无痕窗口（关闭即丢数据）。若浏览器禁用本地存储，页面顶部会出红色提示条，此时数据仅在内存中，刷新即重置。

## 六、数据口径（与项目计划书同源）

| 项 | 取值 |
| --- | --- |
| 点位 | P1 图书馆（超大 12 组 / 480 格口）、P2 A区14公寓（大 6 组 / 240）、P3 B区1-2公寓（大 6 组 / 240）、P4 C区5-6公寓（大 6 组 / 240）、P5 A区教学主楼（小 2 组 / 80）、P6 B区食品工程学院（小 2 组 / 80） |
| 合计 | 6 点位 / 34 组柜体 / 1,360 格口（单组 ＝ 主柜 16 格 ＋ 副柜 24 格 ＝ 40 格口） |
| 温区 | 每组 10 格保温，共 34 × 10 ＝ 340 格口，与概算中「保温加热分区改造」一项对应 |
| 概算总投资 | 1,439,340 元 |
| 效益口径 | 日均外卖 4,200 单 × 使用率 55% ＝ 2,310 单/日；年净现金流 398,400 元；静态回收期 3.61 年 |

## 八、已知限制（如实说明）

- **界面观感未经人工目视验收**：开发环境禁止启动浏览器，界面正确性由 143 项断言与链路脚本保证，视觉层面请在浏览器中自行确认。
- **超时计费为演示规则**：免费 120 分钟、每满 60 分钟加收 1 元、封顶 5 元，非真实商业定价。
- **模拟数据非调研数据**：种子订单与工单为演示分布；渗透率 28%、使用率 55%、骑手单价 0.80 元/单在项目计划书中均明确标注为假设值。
- 楼栋精确经纬度未逐一取点，点位只做相对位置描述，以避免伪造数据。
